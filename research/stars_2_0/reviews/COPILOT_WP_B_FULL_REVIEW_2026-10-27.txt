
### 2. The cross-section function is a phenomenological surrogate, not obviously a literature parameterization

The structure is plausible, but the precise peak values, widths, penetrability caps, baseline normalization, and additive treatment of resonances do not appear to follow directly from the cited paper as written. The paper reports evaluated cross-section and reaction-rate data, but that does not itself validate these particular three Breit-Wigner terms. [2](https://link.springer.com/content/pdf/10.1007/s10894-016-0069-y.pdf)

- interference between channels is absent;
- resonance amplitudes are simply added to a nonresonant term;
- the R2 penetrability ratio contains an empirical cap of `1.5`;
- R3 uses another empirical `min()` factor;
- no covariance or uncertainty band is propagated;
- the polarization factor modifies only the R2 amplitude, but the numerical coefficient is assumed rather than derived in the code.

## 2. The cross-section function is a phenomenological surrogate, not yet a literature parameterization

The paper supports the reaction-energy range and resonance structure, but that does not automatically validate your particular sum of:

- an S-factor baseline,
- three independently added Lorentzians,
- custom penetration-ratio modifiers,
- selected peak values and widths.

Sikora and Weller's paper reports a cross-section evaluation based on experimental alpha yields and notes that the new evaluated reaction rate differs from the previously accepted result by roughly 10–15% over a specified temperature range. [2](https://link.springer.com/content/pdf/10.1007/s10894-016-0069-y.pdf) That is not equivalent to endorsing the exact analytic function in `sigma_pb11_barns()`.

Potential problems include:

- double-counting a nonresonant contribution beneath the resonance terms,
- missing interference between reaction amplitudes,
- imposing a Lorentzian form where an R-matrix or evaluated data table would be more appropriate,
- treating the broad structures as independent additive peaks,
- using a scalar spin multiplier without a channel-resolved polarized cross section.

### Recommended change

Rename the function and document its status:

```python
def sigma_pb11_surrogate_barns(...):
    """
    Phenomenological surrogate for sensitivity studies.
    Not an evaluated cross-section representation.
    """
```

For the next validation stage, ingest digitized or machine-readable evaluated cross-section data and interpolate it. Keep this surrogate only as a comparison model.

At minimum, generate a verification plot over 0.05–4 MeV showing:

1. each component separately,
2. the summed cross section,
3. literature/evaluated data points,
4. residual error.

Unless the recovery apparatus collects both surfaces, this can overstate recoverable alpha energy.

```python
return {
```

Then use forward escaped energy in the downstream recovery calculation. If a magnetic mirror recovers front-going alphas, model it explicitly with a separate reflection and transport efficiency.

## 6. The “2³ factorial” design is causally confounded

This is probably the most important experimental-design issue.

When Acoustic is switched on, the code simultaneously changes:

- target thickness from 50 to 4 µm,
- laser-to-proton efficiency,
- proton spectral shape,
- effective sheath temperature,
- spectral bump.

Therefore, the Acoustic main effect cannot be separated from target thickness, source normalization, or spectral redistribution.

Similarly, Wave changes both:

- stopping drag,
- direct-conversion efficiency.

That makes the eight corners a **scenario matrix**, not a clean factorial experiment.

### Recommended split

Use independent factors such as:

- A: acoustic hardware off/on,
- B: polarization off/on,
- C: wave hardware off/on,
- D: target thickness 4/50 µm,
- E: source spectrum baseline/acoustic,
- F: laser-to-proton efficiency baseline/enhanced.

If a full \(2^6\) study is too expensive, use a fractional factorial, Morris screening, or Sobol sensitivity analysis. The current design can remain, but call it a “bundled architecture scenario matrix.”

## 8. The wall-plug ledger needs a conservation audit

The ledger is readable, but several boundaries need clarification.

### Proton-beam heat

You add the entire proton beam energy to the thermal pool:

```python
E_thermal_pool_J = E_stopped_fusion_J + E_proton_beam_J
```

However, the integrator calculates:

```python
E_protons_exit_J
```

and then does not use it. If protons leave the converter, their remaining kinetic energy is not target heat unless a downstream dump captures it inside the declared thermal boundary.

A first correction is:

```python
E_proton_deposited_J = (
    sim["E_protons_in_J"] - sim["E_protons_exit_J"]
)
```

But even that needs care around reacted protons and accounting boundaries.

### Direct conversion versus residual heat

This line:

```python
E_stopped_fusion_J = sim["E_fusion_born_J"] - E_direct_elec_J
```

can be valid only if every joule not delivered electrically, including converter losses and uncollected alpha energy, ultimately reaches the same recoverable thermal pool. If some energy escapes, strikes non-recovered structures, or remains in outgoing particles, it must be separated.

I suggest explicit ledger terms:

```python
E_alpha_forward_collected
E_alpha_front_escaped
E_alpha_uncollected
E_alpha_converter_loss
E_alpha_direct_electric
E_proton_target_deposition
E_proton_exit
E_other_radiation_escape
E_recoverable_heat
E_unrecoverable_heat
```

Then assert:

```python
abs(E_in - E_out) < tolerance
```

for each subsystem and the full shot.

# Smaller code-quality points

- The source contains mojibake: `â€”` should be `—`, and `um` could consistently be `µm` in output labels or remain ASCII everywhere.

- Reaction probabilities are not removed from the proton weights. That is probably numerically negligible here, but either implement depletion or explicitly assert that the maximum integrated reaction probability is small.
- Normalize discrete proton weights directly so they sum exactly to `N_protons`, rather than mixing trapezoidal normalization with gradient-based quadrature weights.
- Introduce a seeded Monte Carlo or uncertainty sampler for the most assumption-heavy inputs.
