## §5. Key Architectural Decisions from Council Round

### 5.1 Triple-Redundant Provenance System
Three tiers mapped to compliance modes:
- Tier A (Strong): C2PA v2.2+ + AuditChain + Shadow Fingerprint → ENTERPRISE, SOVEREIGN
- Tier B (Medium): AuditChain + Shadow Fingerprint → INTERNAL, RESEARCH
- Tier C (Weak): Disclosure label only → PUBLIC_INFRA fallback

### 5.2 D-106 Reframing
Style Sovereignty reframed from universal enforcement to routing preference layer:
- Open-weight providers: HARD ENFORCE
- Cooperative providers: HARD ENFORCE
- Non-cooperative providers: WARN + LABEL
- Maps cleanly to D-101 Compliance Modes

### 5.3 D-96.2 Compliance Declaration
Every M158–M163 module spec must include explicit D-96.2 compliance block:
- Permitted training corpus: open-weight outputs, licensed datasets, user-owned data, public domain
- Prohibited: stored closed API outputs, other provider closed outputs
- Audit trail: AuditChain canonical entry per training run

### 5.4 Sprint Resequencing (GPT + Notion convergence)
Original: H5-1 (M158+M163) → H5-2 (M159+M161) → H5-3 (M160+M162)
Proposed: H5-1 (M163+M162a+M164) → H5-2 (M158+M161+M165) → H5-3 (M159+M160+M162b)
Rationale: Consent registry + attribution ledger must exist before provenance engine can write to them

### 5.5 Alexa Q Routing
